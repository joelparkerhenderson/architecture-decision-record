# Rejestr decyzji architektonicznych: biblioteka JavaScript Svelte do front-endu

Status: Zaakceptowany

## Kontekst

Tworzymy aplikację internetową z użyciem nowoczesnego frameworka JavaScript do front-endu. Chcemy wybrać bibliotekę, która jest lekka, szybka i łatwa w użyciu. Oceniliśmy kilka bibliotek, w tym React, Vue i Angular. Słyszeliśmy też o Svelte, który twierdzi, że jest nowym rodzajem lekkiego frameworka. Musimy ocenić Svelte i zdecydować, czy dobrze pasuje do naszej aplikacji.

## Decyzja

Po rozważeniu zalet i wad każdej biblioteki postanowiliśmy użyć Svelte jako naszej biblioteki JavaScript do front-endu z następujących powodów:

1. **Lekkość:**  Svelte jest jedną z najlżejszych dostępnych bibliotek, co pomoże nam utrzymać mały rozmiar aplikacji i poprawić czasy ładowania stron.

2. **Szybkość:**  Svelte jest znany z szybkiego renderowania, dzięki czemu nasza aplikacja będzie sprawiać wrażenie responsywnej i żwawej.

3. **Łatwość użycia:**  Składnia Svelte jest prosta i łatwa do zrozumienia, co ułatwi naszemu zespołowi jego przyjęcie i pisanie czystego kodu.

4. **Optymalizacja pod renderowanie UI:**  Svelte jest zoptymalizowany pod renderowanie komponentów UI, co ułatwi nam tworzenie dynamicznych elementów UI wielokrotnego użytku.

5. **Dobra dokumentacja i wsparcie społeczności:**  Svelte ma rosnącą społeczność i dobrą dokumentację, co pomoże nam szybko zacząć i rozwiązywać pojawiające się problemy.

## Alternatywy

Rozważaliśmy React, Vue i Angular, ale zdecydowaliśmy się przeciwko nim z następujących powodów:

1. **React:**  Choć React ma dużą bazę użytkowników oraz bogactwo bibliotek i zasobów, może być złożony i trudny do nauki, zwłaszcza dla początkujących.

2. **Vue:**  Vue to lekka biblioteka, łatwa do nauki i użycia, ale może nie być tak szybka ani zoptymalizowana jak Svelte.

3. **Angular:**  Angular to kompleksowy framework oferujący wiele funkcji i narzędzi, ale może być ciężki i złożony oraz wymagać więcej utrzymania niż Svelte.

## Konsekwencje

Użycie Svelte jako naszej biblioteki JavaScript do front-endu będzie miało następujące konsekwencje:

1. Nasza aplikacja będzie lekka i szybka, co poprawi doświadczenie i zaangażowanie użytkowników.

2. Nasz zespół będzie musiał nauczyć się nowej biblioteki, ale składnia Svelte jest prosta i łatwa do zrozumienia, więc krzywa uczenia się powinna być do opanowania.

3. Svelte jest wciąż stosunkowo nową biblioteką, więc możemy napotkać problemy, które nie są dobrze udokumentowane ani wspierane przez społeczność.

4. Społeczność użytkowników Svelte rośnie, więc w przyszłości może pojawić się więcej bibliotek i zasobów firm trzecich, które można wykorzystać do uzupełnienia biblioteki podstawowej.

## Podsumowanie

Na podstawie naszej oceny postanowiliśmy użyć Svelte jako biblioteki JavaScript do front-endu naszej aplikacji internetowej. Wierzymy, że lekkość i szybkość Svelte, łatwość użycia i zoptymalizowane renderowanie UI czynią go najlepszym wyborem dla naszych potrzeb. Będziemy nadal obserwować rozwój Svelte i jego społeczności i w razie potrzeby zmodyfikujemy nasz wybór.
